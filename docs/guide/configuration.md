# Configuration & Pairing

While most users manage NexusKVM through the desktop graphical user interface (**GUI**), the system is driven by transparent, declarative configuration files in **TOML** and **JSON** formats.

---

## 1. Configuration File Locations

| Mode | Base Directory | Files |
| :--- | :--- | :--- |
| **User Mode (Default GUI)** | `~/.config/nexuskvm/` | `daemon.toml`, `layout.json`, `server.crt`, `server.key` |
| **System Mode (systemd / GDM)** | `/etc/nexuskvm/` | `daemon.toml`, `layout.json`, `server.crt`, `server.key` |

---

## 2. Server Daemon Configuration: `daemon.toml`

Defines parameters for the `nexus-kvmd` server on the Host:

```toml
# Network interface and port for incoming client connections
listen_address = "0.0.0.0:5258"

# Unix socket path for local control plane (used by nexusctl and GUI)
socket_path = "/run/user/1000/nexuskvm.sock"

# Physical key shortcut to cycle between Host and connected Clients
switch_keys = ["KEY_LEFTALT", "KEY_LEFTCTRL"]

# Path to TLS certificates
certificate_path = "/home/user/.config/nexuskvm/server.crt"
key_path = "/home/user/.config/nexuskvm/server.key"
```

## 3. Screen Layout Topology: `layout.json`

Specifies the physical spatial arrangement of displays across all paired computers:

```json
{
  "screens": [
    {
      "id": "host-primary",
      "name": "Host (Workstation)",
      "width": 2560,
      "height": 1440,
      "is_host": true
    },
    {
      "id": "client-laptop",
      "name": "Secondary Laptop",
      "address": "192.168.1.50:5258",
      "width": 1920,
      "height": 1080,
      "is_host": false
    }
  ],
  "links": [
    {
      "source_id": "host-primary",
      "edge": "right",
      "target_id": "client-laptop",
      "target_edge": "left",
      "start_percent": 0,
      "end_percent": 100
    },
    {
      "source_id": "client-laptop",
      "edge": "left",
      "target_id": "host-primary",
      "target_edge": "right",
      "start_percent": 0,
      "end_percent": 100
    }
  ]
}
```

### Link Parameters:
- `edge`: Active trigger border (`"left"`, `"right"`, `"top"`, `"bottom"`).
- `start_percent` / `end_percent`: Defines **partial boundary zones** (e.g., crossing only through the upper half when displays differ in physical height).

---

## 4. Pairing Code Structure

The pairing token generated by the UI is a compact Base64-encoded string containing:
1. The **IP address and port** of the Host on the local network.
2. The **cryptographic fingerprint (SHA-256)** of the Host's TLS certificate.
3. A **session authentication token**.

When pasted into the client, it automatically validates the identity of the host and performs a secure TLS 1.3 handshake.
